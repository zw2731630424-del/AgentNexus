# M1.7 architecture — first implementation plan

Scope: a trusted local native collaboration pilot, based on the byte-verified M1.6.1 source. All models remain SIMULATED. Strict cumulative CPU, production process execution, and external effects remain BLOCKED. The source is separate from the root product and from all historical deliveries.

The Development task consumes original requirements and rules through Context Assembly, then produces a structured proposal through the simulated Model Gateway. A trusted admission layer validates the bounded dependency graph, role grants, exact output ownership, resource requirements, and acceptance contracts. It materializes accepted tasks without granting model output administration capabilities. Every delegation, question, follow-up, artifact handoff, and review notice travels through the persistent Message Bus.

The three independent implementation tasks produce a task data model, task analytics, and a CLI adapter in distinct workspaces. Research and architecture precede them; test, debug, review, documentation, integration, and delivery follow their real dependencies. The simulated provider contains explicit fixture generation strategies; those fixture strategies are Codex-authored engineering input. Pilot files themselves must first appear from actual Native Agent Loop / Gateway / Storage Owner execution. This proves local orchestration and data provenance, and does not prove general model-driven autonomous software engineering.

An event-driven Resident control plane owns a bounded durable dispatch queue. It sleeps on events/deadlines, performs no idle model requests, resumes only known safe waiting tasks, and leaves UNKNOWN effects quarantined. A narrow Coordinator adapter can inspect granted project status and rank ready work. Neither role can edit source, rules, policy, goals, or audit records.

The fixed test runner is a trusted Host quality checker, with an exact executable and fixed arguments. It only runs candidates admitted by an immutable source manifest and a host-owned fixture allowlist. It never exposes arbitrary shell/process execution to an Agent. The local runner is not a production OS sandbox. Its stdout, stderr, exit, candidate hashes, and test profile become immutable evidence. Independent reviewers receive diff/candidate/original source context, return findings over Message Bus, and cannot write development code. The Development task decides repairs; Debug receives a separate contract and Storage Owner version-bound replacement authority.

G0–G6 use M1.6.1 NativeGateEngine semantics: admission, input integrity, plan, code/tests, independent review, delivery evidence, final local acceptance. A manifest validator binds each actual file and Storage Owner version to the candidate set. This is a verified multi-file delivery set, not a multi-file atomic publication transaction. Model self-reported PASS, missing evidence, stale hashes, simulated safety claims, and disabled gates cannot grant protected execution.

Model Gateway adds only a trusted in-memory simulated responder hook, capability metadata/routing, and explicit opaque mock credential handles. The hook sees exact reconstructed model context and public subject metadata; it receives no Store, admin token, credentials, network adapter, or raw filesystem handle. Its replies and usage pass the existing schema and budget checks. Key handles are not included in model input. Real providers remain rejected.

Evidence is divided into: (1) Codex engineering changes and independent engineering review, (2) actual Native Harness pilot traces with simulated model provenance, (3) inherited historical failures, and (4) qualifications/NOT_RUN items. The default pilot is bounded and reproducible. A separate two-hour event-driven soak is run only if the host session supports sustained observation; short tests never stand in for the two-hour result. Real Host process interruption and safe restart are tested separately from OS reboot and power loss.
