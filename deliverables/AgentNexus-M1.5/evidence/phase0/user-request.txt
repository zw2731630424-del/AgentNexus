# AgentNexus M1.5 — Production Bootstrap & Security Execution Closure

**项目：** AgentNexus v0.4  
**开发基线：** M1.4  
**执行代理：** Codex  
**任务性质：** 生产启动链、独立身份、Broker、可信 IPC、组合沙箱和进程退出证明。

# 一、核心目标

AgentNexus 已完成 M0、M0.1、M1、M1.2、M1.3 和 M1.4。

M1.4 已经实现并验证部分：

- Runtime Identity。
- Remote Permit。
- Windows 原生 Token、Job Object、Named Pipe。
- File Broker。
- ExitProof 候选机制。
- Resource Reconciliation。
- 审计生产者接口。

但完整 Windows 生产执行链仍然 BLOCKED。

本轮不推倒现有成果，也不重复实现已经通过验证的原语。

本轮核心目标：

**让 Host 能够通过可信启动链创建独立 Worker，Worker 通过受保护 IPC 接收精确授权，在 Windows 隔离环境中执行有限任务，最终由可信 Supervisor 确认完整进程树退出，并根据 ExitProof 安全释放资源。**

最终执行链：

```text
Host Bootstrap
      |
      v
Host Runtime Identity
      |
      v
Policy / Approval / Permit
      |
      v
Production Broker
      |
      v
Authenticated IPC
      |
      v
Worker Bootstrap
      |
      v
Restricted Token + AppContainer + Job
      |
      v
File Broker
      |
      v
Controlled Worker Execution
      |
      v
Process Tree Observation
      |
      v
ExitProof
      |
      v
Resource Reconciliation
      |
      v
Audit Trail
```

不能将局部原语测试通过描述为完整执行链通过。

# 三、P0：Production Bootstrap

这是本轮最重要的基础工作。

M1.4 已经明确，生产 Host/Broker/Worker 启动入口和持久 IPC Bootstrap 尚未形成完整实现。

现在需要真正建立。

## 3.1 Host Bootstrap

实现可信 Host 启动流程：

1. 确认当前 OS 用户身份。
2. 验证 Host SID。
3. 验证启动目录和程序指纹。
4. 验证配置文件版本。
5. 验证数据库和存储目录权限。
6. 初始化可信 Control Plane。
7. 初始化 Policy。
8. 初始化 Broker。
9. 创建受保护 IPC Endpoint。
10. 启动 Supervisor。
11. 恢复未完成 Operation。
12. 完成启动审计。

Host 不得依靠 Agent 请求中的身份字段证明自己是 Host。

Host 管理权限必须由受信任的启动链持有。

## 3.2 Worker Bootstrap

Worker 必须由可信 Supervisor 创建。

要求：

- Worker 使用独立 OS 身份。
- Worker 具有独立 Worker Instance ID。
- Worker 绑定 Project、Task、Session。
- Worker 绑定 Sandbox Profile。
- Worker 只取得完成任务所需的能力。
- Worker 不获得管理数据库权限。
- Worker 不获得 Admin Capability。
- Worker 不得自行创建新的授权身份。
- Worker 退出或撤销后身份失效。

必须验证进程启动、身份绑定、IPC 连接和权限撤销的完整生命周期。

## 3.3 启动方式

根据实际验证结果选择合适的 Windows 用户态启动方案。

可以研究 Task Scheduler 的受限启动方式，但必须先确认：

- 登录权要求。
- 密码安全处理。
- Task 安全上下文。
- 启动权限。
- 重复启动控制。
- 崩溃恢复。
- 进程终止和退出观察。

不要未经论证就安装 Windows Service 或授予管理员权限。

# 四、P0：Production Broker 与 Trusted IPC

建立真正长期运行的 Broker。

## 4.1 Broker

Broker 必须：

- 验证实际 IPC Peer。
- 验证 Runtime Identity。
- 验证 Worker Instance。
- 验证 Operation ID。
- 验证精确 Permit。
- 验证 Resource ID。
- 验证 Policy Epoch。
- 验证 Feature Epoch。
- 验证 Sandbox Profile Hash。
- 创建 Worker。
- 监管 Worker 生命周期。
- 收集输出。
- 记录操作结果。
- 生成退出证明候选。

所有高风险执行只能经过 Broker。

不允许出现 Agent 直接执行宿主机命令的旁路。

## 4.2 Remote Permit

保留 M1.4 已有精确授权设计。

授权必须绑定：

- Agent Identity。
- Runtime Identity。
- Worker Instance。
- Operation ID。
- Intent Hash。
- Tool ID / Version。
- Resource ID。
- Sandbox Profile。
- Policy Epoch。
- Feature Epoch。
- Nonce。
- Expiration。
- 使用次数。

授权消费必须原子化。

IPC 中断不允许自动重放副作用操作。

## 4.3 Named Pipe

完成生产 Named Pipe Endpoint。

要求：

- 精确 Pipe ACL。
- Peer SID 验证。
- Peer Process Identity 验证。
- Worker Instance 绑定。
- MAC 验证。
- Nonce 防重放。
- 请求期限。
- 连接撤销。
- 消息长度限制。
- 并发连接上限。
- 未完成请求上限。

必须区分：

原语测试 PASS 与生产 IPC 组合 PASS。

## 6.1 文件访问

Worker 只能通过 File Broker 访问授权资源。

要求：

- 工作区路径精确绑定。
- 文件句柄级访问。
- 路径规范化。
- 符号链接拒绝。
- Junction 拒绝。
- Hardlink 边界检查。
- TOCTOU 防护。
- 文件大小限制。
- 目录遍历限制。
- 读取和写入审计。
- 不允许访问 Host 管理数据库。
- 不允许访问其他项目。

尤其不能使用简单字符串前缀判断文件是否属于授权工作区。

## 6.2 网络访问

默认拒绝。

不授予 Worker 不必要的网络能力。

需要外部网络时必须另行定义明确的网络授权和执行边界。

不得因为某次测试没有成功连接网络，就直接认定所有网络访问路径都已被阻断。

## 6.3 CPU 限制

M1.4 的 CPU 硬限制曾经出现真实 FAIL，后续出现 PASS。

本轮必须单独处理。

要求：

- 核实限制的实际作用对象。
- 核实 CPU 时间与墙钟时间区别。
- 核实子进程是否计入。
- 核实 Job 中全部进程的计量。
- 核实终止边界。
- 多次重复测试。
- 保存完整原始记录。

在稳定性资格测试完成前，不得宣称 CPU Hard Limit 已经具备生产保证。

# 七、P0：ExitProof 完整闭环

M1.4 已经具有 ExitProof 候选机制，但生产 ExitProof 仍然 BLOCKED。

本轮必须实现真正的退出确认。

至少验证：

1. Worker 主进程退出。
2. Job 内全部成员退出。
3. 子进程没有残留。
4. stdout/stderr Producer 已经停止。
5. IPC 请求已完成或明确进入未知状态。
6. Sandbox 状态已关闭。
7. 资源所有者确认释放条件。
8. ExitProof 记录持久化成功。

状态至少区分：

- TERMINATION_REQUESTED。
- PROCESS_EXITED。
- PROCESS_TREE_EXITED。
- OUTPUT_SETTLED。
- EXIT_VERIFIED。
- EXIT_UNVERIFIED。

任何一项不完整，都不得自动释放对应资源。

不要把进程句柄失效、发送终止信号、父进程退出或 Job 查询结果中的单一信号直接等同于完整退出证明。

# 八、P0：Resource Release

只有完整 ExitProof 和资源所有者验证均通过，才能考虑开放对应资源释放。

必须保留：

- M1.2 Writer Claim。
- M1.3 UNKNOWN_QUARANTINED。
- M1.4 五类资源独立投影。
- 原始 Operation。
- 原始 Intent Hash。
- 历史裁定记录。

未知状态不能自动释放。

生产 Release 必须经过独立策略和资源所有者授权。

不得为了避免任务阻塞而绕过不确定状态。
