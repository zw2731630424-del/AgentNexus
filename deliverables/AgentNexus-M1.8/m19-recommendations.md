# M1.9 实施建议

先解决凭证服务与 Worker 的独立身份/文件隔离资格，并由用户单独批准部署方案；DPAPI CurrentUser 本身不能隔离同账户进程。Ubuntu Secret Service/独立服务必须有实际运行证据，禁止明文 fallback。生产 OS、严格累计 CPU 和任意模型生成代码的执行资格仍分别处理。

随后按真实 Provider 联调申请逐项批准一次小额 smoke，再开展双 Subagent、只读 Reviewer 和 Debug 的真实 Pilot。必须补足真实模型能力/价格/缓存计费和响应别名证据、TLS/代理/超时/拒绝/费用对账，以及 UNKNOWN 的独立 Owner reconciliation；不能用普通 settle 释放未决费用。

执行真实 24 小时 Resident；当前新的有界 runner 仅提供执行入口。将实际本地 Commit/Push 事件源接 Host watcher，持续更新 head；当前 push 是可信 Host 本地事件接口，未安装 Hook 或建立远端观察服务。冻结候选再运行预注册 A/B/C 对照，扩大样本后才讨论质量优势。

本轮未解除的历史 CPU/Windows 原语失败保留为独立阻断账本。不要用回归偶然通过覆盖资格失败，不扩大 Coordinator、Reviewer 或模型的权限。
