# 内容快照、路径与输出事务审查

用户看到的最终 JSON 先保存为不可变内部快照；相同 UTF-8 LF 字节用于内容 Hash、CMS 和输出。UI 仅将换行转换为 CRLF 显示。调用者得到快照副本，不能修改内部原件。

完整载荷和元数据读取后保存在内存，保留原只读句柄。所有文件数、总字节、清单、app 闭包、工具和元数据 Hash 绑定到该快照。单文件上限 512 MiB、单 bundle 快照总量上限 768 MiB，内存不足或超限失败关闭。实际导出/readback 会有多份快照，必须保留足够内存；本轮 194 项公开准备流程另有完整测试。

在加载、最终 Yes 后、执行签名前、导出和提交标记前复核源集合和实际句柄内容。文件替换/写入的普通句柄攻击被共享模式限制；文件映射、管理员、内核和已失陷签名设备不能由普通共享标志概括为全面隔离。独立既有写映射探针在获取阶段即被拒绝，没有冒称执行了映射成功后的篡改场景。

路径必须是完全限定的本地 Fixed/Removable 卷。目录从卷根逐级打开，使用 0x81（LIST_DIRECTORY + READ_ATTRIBUTES）、仅共享读、OPEN_REPARSE_POINT，并核对实际句柄类型/属性。叶文件同样不跟随重解析点。目录句柄禁止写与删除，防止空目录被改成 junction 或祖先被置换；输出探测、公钥读取、预览和准备工具均遵循这一方向。

本轮确实发现仅用 0x80 的属性句柄仍允许写句柄打开，故第一次专门测试失败。改为 0x81 后实际写入探针返回 Windows sharing violation 32；独立复核还确认释放目录锁后同一写入能成功。失败运行保留，未将失败改写成通过。该结果只验证所测文件系统控制，不授予原 70 项 OS 资格。

输出事务独占创建新根目录及子目录，文件一律 CreateNew。文件写入、Flush 后保持写句柄，仅允许其他读取；readback 使用兼容的读取共享方式，原写句柄继续禁止外部写入。实际输出的完整文件集合、Hash、CMS 和语义绑定在签名提交标记前后重新读取验证。已有目录、文件、额外文件/目录、写入或 rename 竞争均拒绝。

中断测试通过诊断构建在真实 Export 的复制/提交阶段结束进程，不生成用户签名。发布符号只编入 harness，不进发布 PE。提交标记前的半成品拒绝；提交标记后进程退出的完整已验证计划可能继续通过计划验证，表示该提交点已完成，仍不批准安装。所有半成品和日志保留，不自动续写、清理或重签。

公开准备工具使用相同 Windows 句柄策略的 Python 实现，先读取/Hash 全工具快照，再通过原 Verifier 的内存 PE 和同一公开 DER 检查证书，不按原路径重新执行。写出后复验实际文件，最后发布绑定 id/epoch/manifest 的准备完成标记。Signer 仍独立核验全部成品。系统网络阻断、防驱动行为与独立桌面安全未在本轮证明；这里只声明代码的文件路径约束与所测控制。
