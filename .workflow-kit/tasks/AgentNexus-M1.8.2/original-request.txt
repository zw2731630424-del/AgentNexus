# 四、P0-B：Credential Vault 生产资格闭合

这是本轮最重要的安全工作。

M1.8.1 的生产 Vault 仍然 BLOCKED。

在真实 API Key 使用之前，必须证明：

1. Host 能够通过可信入口取得授权凭证。
2. 普通 Agent 无法读取完整 API Key。
3. Subagent 无法读取父 Agent 的凭证。
4. Reviewer 无法访问 Vault。
5. Worker 无法直接读取 Vault 文件。
6. API Key 不进入 Prompt。
7. API Key 不进入 Context Archive。
8. API Key 不进入普通 Audit 正文。
9. API Key 不进入错误日志。
10. API Key 不通过命令行参数传递。
11. API Key 不通过不受控环境变量传递。
12. Key 撤销后旧 Handle 失效。
13. Key 轮换期间不会发生未授权访问。
14. Host 重启后凭证状态能够安全恢复。

## 4.1 凭证存储方案

结合当前真实运行环境研究：

- Windows DPAPI。
- Windows Credential Manager。
- OS 身份绑定。
- Host-only Credential Service。
- 独立凭证文件及 ACL。
- Ubuntu 后续 Secret Service / 系统密钥环适配。

不必为了本轮同时完成 Windows 和 Ubuntu 两套生产部署。

但接口必须保持跨平台。

## 4.2 安全凭证入口

必须提供真正安全的凭证录入方式。

要求：

- 用户能够直接向可信 Vault 输入 Key。
- 不通过聊天发送 Key。
- 不通过普通终端参数传递 Key。
- 不将 Key 写入临时文件。
- 不将 Key 放入普通环境变量。
- 输入完成后立即交由可信凭证服务处理。
- 日志和审计只记录 Credential Handle ID。
- 普通 Agent 只能发起授权请求，不能读取凭证。

不要为了尽快接入 DeepSeek 而绕过 Vault。

如果当前生产 OS 身份、ACL 或启动链仍然无法保证凭证隔离，继续 BLOCKED。

## 4.3 资格测试

至少测试：

- 非授权进程访问。
- 普通 Agent 访问。
- Subagent 访问。
- Reviewer 访问。
- Worker 访问。
- 错误 Handle。
- 过期 Handle。
- 已撤销 Handle。
- 并发请求。
- Host 重启。
- 异常退出。
- 日志泄漏。
- Prompt 泄漏。
- 文件读取泄漏。

只有真实生产隔离证据通过，才能标记 LIVE_VAULT_QUALIFIED。

模拟测试不能替代真实 OS 权限验证。

- PUBLIC。
- SYNTHETIC。
- INTERNAL。
- CONFIDENTIAL。

|---|---|

| INTERNAL | 默认拒绝外发 |

| SECRET | 禁止外发 |

- Context Hash。
- Request Hash。
- 数据来源清单。

- 数据准入结果。

- Model ID。
- Endpoint。

- 是否包含项目内部规则。

- 是否包含本地文件路径。

## 5.3 Data Egress 失败行为

不能让 Agent 自己声明 PUBLIC 后直接放行。
