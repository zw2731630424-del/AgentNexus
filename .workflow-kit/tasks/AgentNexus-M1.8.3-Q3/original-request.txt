## 一、核心任务

本轮不再扩大 AgentNexus 的整体架构。

M1.8.3-Q2 已经交付：

- 独立 C# WinForms Trusted Credential Helper。
- 普通权限有限启动器。

- Daily Grant 协议。
- 请求 Hash、Nonce、Epoch 和 Context 绑定。
- Token Ledger 原子预算管理。
- Data Egress。
- 合成跨进程 IPC。
- 215 PASS / 0 FAIL / 2 SKIP 的限定回归。

但 Q2 整体仍然 BLOCKED。

关键缺口：

1. Trusted Helper 尚未通过实际 UAC 启动并显示可信录入窗口。
2. Credential Service 尚未真实部署。
3. 生产 Native Runtime 来源认证器尚未实现。
4. 服务创建、启动和监管可信 Runtime 的机制尚未实现。
5. Medium Integrity 日常 IPC Listener 尚未实现。
6. 普通权限 AgentNexus 不能实际调用模型，目前返回 IPC_BLOCKED。
7. 70项真实 Windows OS 资格测试全部 NOT_RUN。

**本轮目标是完成可信凭证录入和日常模型调用两条完整执行链，不再停留在协议、Fixture 和模拟 API 的单独测试。**

必须同时保证：

- 日常启动 AgentNexus 不需要管理员权限。
- 添加 API Key 时才触发 UAC。
- 正常 Agent 模型请求不触发 UAC。
- 普通 Agent 无法读回完整 API Key。
- 不建立无授权限制的通用高权限代理。
- 未取得生产资格前不导入真实 Key。

## 三、P0-A：实现真正可启动的 Trusted Helper

完成 Q2 已编译 Helper 的实际启动链。

目标：

```text
AgentNexus Desktop
        |
        v
点击 Add Key
        |
        v
固定受控启动器
        |
        v
Windows UAC
        |
        v
Trusted Credential Helper
        |
        v
独立 API Key 录入窗口
        |
        v
Credential Service
        |
        v
保存结果与安全状态
        |
        v
Helper 退出
```

### 必须实现

1. 普通权限 Electron 能发起固定 Add Key 操作。
2. 受控 Launcher 只能启动受保护的可信 Helper。
3. 不接受任意可执行路径、命令、脚本或 URL。
4. UAC 只针对本次凭证操作。
5. Helper 显示独立可信表单。
6. 用户在 Helper 中输入凭证。
7. 原 Renderer 不接收明文 Key。
8. Helper 将凭证通过受认证 IPC 提交。
9. 服务返回保存确认或明确失败状态。
10. Helper 退出并清理临时资源。
11. 原 UI 刷新凭证元数据。

保留 Q2 已完成的 Ticket、Hash、Epoch、Operation 和 Channel 绑定机制。

不得重新实现第二套 Ticket 协议。

### 特别验证

处理两种 Windows 情况：

- 当前用户是管理员，通过 UAC 同意进行提升。
- 当前用户是标准用户，需要另一管理员凭证进行提升。

不能将提供 UAC 凭证的管理员身份自动等同于原操作用户的授权身份。

如果当前协议无法安全支持第二种情况，明确限制并显示错误，不得绕过验证。

### 内存与进程安全

重点保护可信 Helper 的实际进程、子进程、加载文件、句柄及凭证传递路径。

不得仅以 High Integrity 或固定文件 Hash 宣称防注入已证明。

明确区分可由常规 Windows 权限隔离保证的内容、需要附加隔离机制的内容，以及无法在当前威胁模型下绝对保证的内容。

不应为了追求无法证明的绝对内存安全而无限期阻塞正常工程开发；但未满足的安全条件必须如实记录。

## 四、P0-B：实现可信 Runtime 的生产启动链

这是本轮最高优先级。

Q2 最大缺口是：

**Daily Grant 已实现，但没有可被 Credential Service 可信识别的生产 Runtime。**

必须完成：

1. Runtime 的固定启动入口。
2. Runtime 的身份和权限定义。
3. Runtime 实际启动与退出。
4. Credential Service 对 Runtime 生命周期的监管。
5. Runtime 与授权 Session 的绑定。
6. 请求通道的创建和关闭。
7. Runtime 崩溃后的恢复与撤销。
8. 原有 Agent Runtime 的兼容集成。

### 架构选择

优先研究并选择能够在当前 Windows 环境部署的最小方案。

候选方案包括：

- 由可信服务创建并监管受限 Runtime。
- 使用操作系统提供的隔离身份或受限 Token。
- 具有不可随意复制授权能力的受控 Broker。
- 其他有实际 Windows API 支持的进程隔离方案。

禁止仅凭 PID、进程路径、Hash 或自报 Agent ID 完成身份认证。

不要假定普通同 SID 进程一定无法注入、打开句柄或操纵其他普通进程。

如果需要 Windows AppContainer、独立 Token、额外服务或其他 OS 机制，必须给出实际可实现的代码和部署要求。

不要只提交概念设计。

### 重要安全原则

必须区分：

- Windows 用户身份。
- 操作系统隔离身份。
- AgentNexus Runtime 身份。
- Agent / Task 逻辑身份。
- 具体模型请求授权。

这几者不能互相替代。

如果选定方案不能满足原本的强同 SID 攻击者威胁模型，应准确说明安全边界和残余风险，不得把协议检查通过宣称为 OS 隔离通过。

## 五、P0-C：实现 Medium Integrity Daily Gateway

目标：

**普通权限 AgentNexus 能够日常调用模型，不再返回 IPC_BLOCKED，也不必每次弹出 UAC。**

必须实现实际可用的生产日常 IPC 入口。

不要把原有高权限管理 Pipe 直接开放给 Medium 进程。

### 通道划分

管理通道：

- 凭证添加。
- 凭证轮换。
- 凭证撤销。
- 其他需要高信任权限的配置操作。

日常通道：

- Agent 模型请求。
- Subagent 模型请求。
- Reviewer 模型请求。
- 请求取消。
- Streaming。
- Usage 读取。
- 受限状态查询。

两个通道必须具有不同权限。

日常通道不得提供：

- API Key 读回。
- Vault 解密。
- 任意 HTTP 代理。
- 任意 Shell。
- 任意文件读取。
- 任意系统配置修改。
- 原始 Token Ledger 修改。
- 任意权限签发。

### 复用 Q2 Daily Grant

必须继续使用现有：

- Runtime Identity。
- Task / Project / Agent。
- Request Hash。
- Context Hash。
- Provider / Model。
- Operation ID。
- Nonce / Epoch。
- Token Reservation。
- Data Egress。
- 审计。

不要开发另一套平行授权系统。

重点是将现有协议接入真正可信的 Runtime 与 IPC。

### 必须形成完整执行流程

```text
AgentNexus 普通权限 UI
         |
         v
Development Agent / Subagent
         |
         v
Model Gateway
         |
         v
可信 Runtime
         |
         v
受限 Daily IPC
         |
         v
Credential Service
         |
         +-- 身份与 Grant 验证
         +-- Data Egress
         +-- Token 预算
         +-- 凭证使用
         |
         v
Provider Adapter / Synthetic Provider
         |
         v
Streaming Response
         |
         v
AgentNexus UI
```

正常模型调用过程中不出现 UAC。

不得让 Trusted Helper 成为长期常驻的高权限通用代理。
