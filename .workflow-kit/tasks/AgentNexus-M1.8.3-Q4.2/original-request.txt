# 三、P0：Qualification Signer 独立安全审查

这是本轮最高优先级。

Signer 虽然独立于 Codex 运行，但其源码和构建产物仍然来自 AgentNexus 开发链。

因此不能简单认为它已经可信。

必须安排独立审查者，对 Signer 的源码、构建结果和实际签名行为进行独立检查。

## 3.1 私钥安全

确认：

1. Signer 不接受 PFX。
2. Signer 不接受 PEM 私钥。
3. Signer 不接受私钥明文。
4. Signer 不接收私钥密码。
5. Signer 不把私钥写入普通文件。
6. Signer 不把私钥传递给 Codex。
7. Signer 不把私钥传递给 Agent。
8. Signer 不向日志写入私钥。
9. Signer 不向网络发送任何内容。
10. Signer 不自动创建或信任证书。

使用 CNG / TPM CNG 时，验证实际 Key Provider、Key Container、Export Policy 和调用权限。

特别区分：

- 私钥不可导出。
- 私钥不可被普通进程调用。
- 私钥调用需要用户确认。

这三者不是同一件事。

NonExportable 不代表同 SID 恶意进程不能调用签名接口。

如果无法证明更强的隔离，明确记录剩余风险。

## 3.2 签名内容完整性

重点审查 TOCTOU：

1. Signer 读取待签署文件。
2. Signer 计算 Hash。
3. UI 展示最终内容。
4. 用户确认。
5. Signer 执行签名。

必须确保这五步之间不会发生内容替换。

优先采用：

- 只读文件句柄。
- 文件内容快照。
- 完整文件 Hash。
- 文件数量和总字节数核验。
- 锁定待签署内容。
- 最终签名绑定实际快照。
- 完成后重新验证输出。

不能仅仅先计算 Hash，然后重新打开原始路径读取内容进行签名。

必须保证：

**用户看到的内容，就是最终实际签署的内容。**

## 3.3 证书验证

至少检查：

- DER SHA256 Pin。
- Subject。
- Issuer。
- Serial Number。
- 有效期。
- Key Usage。
- EKU。
- Public Key Algorithm。
- Signature Algorithm。
- CMS SignerInfo。
- 签名验证结果。
- 私钥与公开证书匹配关系。

LOCAL_QUALIFICATION 只能使用用户独立确认的本地信任锚。

不得因为证书是本机生成的就自动信任。

不得把 Subject 名称相同视为证书相同。

实际信任必须绑定 DER SHA256 Pin。

## 3.4 签名算法

检查：

- 是否使用 SHA-256 或更强的批准算法。
- 是否拒绝 MD5。
- 是否拒绝 SHA-1。
- 是否拒绝弱密钥。
- 是否拒绝不支持的算法。
- 是否正确验证 CMS。
- 是否存在算法降级。
- 是否存在证书替换。

具体算法必须记录在签名合同中。

不能依赖默认算法而不记录实际结果。

# 四、P0：独立 Signer 的运行环境

Signer 应该运行在与 Codex 开发环境隔离的签名环境中。

建议优先：

1. 独立 Windows 设备。
2. 独立 Windows 用户和登录会话。
3. 用户控制的 CNG / TPM 密钥。
4. 不允许 Agent 访问私钥。
5. 不允许 Codex 控制签名桌面。
6. 不允许自动化代理静默调用签名功能。

不必强制购买 TPM 硬件。

如果当前设备没有 TPM，也可以研究软件 CNG Key Storage Provider，但必须明确其安全边界。

如果选择软件密钥，不能声称它具备 TPM 的硬件隔离能力。

## 重要要求

Signer 的独立性不只是文件分开。

还包括：

- 私钥访问主体独立。
- 签名桌面独立。
- 用户确认独立。
- 最终待签署内容独立核对。

如果这些条件不能满足，必须标记 INCONCLUSIVE。

# 五、P0：本地证书准备流程

本轮需要准备一套清晰的用户操作流程。

但不要擅自创建证书或导入信任。

## 5.1 证书方案

优先支持：

- Windows CNG Key Storage Provider。
- TPM-backed CNG（设备支持时）。
- 用户独立控制的 CurrentUser My。
- 不可导出私钥。
- SHA256 证书指纹。
- 明确证书有效期。

如果创建脚本需要修改 CurrentUser My，必须在 UI 中清楚展示。

不得自动导入 Root 或 Trusted Publishers。

## 5.2 用户操作界面

Signer 应显示：

- 证书名称。
- Subject。
- Issuer。
- Serial Number。
- DER SHA256 Pin。
- 有效期。
- Key Provider。
- Key 是否可导出。
- Key 是否需要交互确认。
- LOCAL_QUALIFICATION 模式。

用户必须能够独立核对证书指纹。

不得仅显示一个证书名称然后要求用户点击确认。

## 5.3 不需要商业证书

本地资格签发不要求购买商业代码签名证书。

但必须明确：

- 本地资格证书只用于指定设备的资格部署。
- 不能冒充商业 CA。
- 不能自动用于生产发布。
- 不能自动获得 Windows 公共信任。
- 不能绕过 Authenticode 或企业发布策略。
